# Query clusters over separate SSH sessions instead of Slurm -M

Slurm commands accept `-M` to query multiple clusters in one client invocation, which appears simpler than managing parallel SSH workers. `sglance` instead opens one SSH session per remote cluster entry in parallel, passing `-M` only when a single login host fronts a specific named Slurm cluster, because `sinfo -M` and `squeue -M` open direct MUNGE-authenticated RPCs to remote `slurmctld` ports and fail whenever clusters run separate `slurmdbd` databases, distinct MUNGE keys, different login usernames, or firewalled controller networks. Paying one SSH invocation per cluster, amortized by the caller's existing `ControlMaster` sockets, allows independent institutions and clusters to sit in one configuration with isolated per-cluster failures.
